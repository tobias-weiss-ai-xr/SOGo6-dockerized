# SOGo6 MCP sidecar

A minimal [MCP](https://modelcontextprotocol.io) (Model Context Protocol) server that exposes the
SOGo6 **agent action facade** (`/api/user/v1/agent/*`) as MCP tools — one tool per manifest action
(27 tools). It lets AI clients (Claude Desktop, Cursor, custom agents, …) operate on the user's
mail, calendar, contacts and AI-assist features through standard MCP tool calls.

It is intentionally **dumb**: no business logic, no database, no Redis, no stored credentials.

```
MCP client ──(streamable HTTP, Bearer token)──► sogo6-mcp (this sidecar)
                                                  │  forwards verbatim
                                                  ▼
                                        SOGo6 REST facade  /api/user/v1/agent/*
                                                  │
                                                  ▼
                                     SOGo6 server (auth + business logic)
```

## How it works

- **Tools come from the manifest, not from hardcoded code.** On startup the sidecar fetches
  `GET {SOGO_AGENT_API_URL}/agent/manifest` from the facade — the facade's `ACTIONS` registry is
  the single source of truth for the tool list.
- **Snapshot fallback.** The live manifest endpoint is *authenticated* (the facade rejects
  anonymous callers with `S000203`), so an uncredentialed sidecar cannot fetch it at boot on real
  deployments. When the live fetch fails (401, boot-time 503, network), the sidecar falls back to
  the bundled [`manifest_snapshot.json`](manifest_snapshot.json) — a build-time copy of the same
  registry, generated by [`gen_manifest_snapshot.py`](gen_manifest_snapshot.py). Boot therefore
  never hard-fails; the exported tool list stays registry-exact.
- **Tools forward, they don't execute.** Each tool takes the action's path parameters plus an
  optional `data` object (query params for GET/DELETE, JSON body for POST/PATCH/PUT). It forwards
  the caller's `Authorization` header verbatim to the facade and returns the facade's envelope
  (`error_code` / `error_msg` / `data`). No parsing or rewriting in between.

## Authentication

The sidecar holds **no credentials**. Every MCP client must send the user's SOGo6 bearer token in
the HTTP `Authorization` header. The sidecar:

- forwards it verbatim (never inspects, never stores it);
- answers `S000208 "Missing bearer token"` if no `Authorization` header is present.

> ⚠️ The MCP endpoint is bound to `127.0.0.1:9000` by default. Front it with a reverse proxy
> (and TLS) before exposing it to remote agents. Never expose it unauthenticated: the tools are
> thin proxies over the user's mailbox.

## Running

### Locally (dev)

```bash
cd deploy/sogo6-mcp
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
SOGO_AGENT_API_URL=http://127.0.0.1:5001/api/user/v1 .venv/bin/python server.py
```

### Docker (compose)

```bash
docker compose --profile agents up -d sogo6-mcp
```

The compose service (`docker-compose.yaml`) sets `SOGO_AGENT_API_URL`, publishes
`127.0.0.1:9000:9000`, limits the container to 0.5 CPU / 128M and applies a Docker-level proxy
bypass (daemon-injected `HTTP(S)_PROXY` must not route internal `sogo6-net` calls through an
external proxy — that shows up as opaque `503` squids errors).

### Health & readiness

```bash
docker inspect --format '{{.State.Health.Status}}' sogo6-mcp
# (docker compose ps shows "healthy" once a POST /mcp initialize returns 200)
```

## Using it from an MCP client

```bash
# Claude Desktop / compatible client
claude mcp add sogo6 --transport http --url http://127.0.0.1:9000/mcp \
  --headers '{"Authorization": "Bearer <sogo6-jwt>"}'
```

Same pattern for any streamable-HTTP MCP client (Cursor, custom agents, etc.): set the
`Authorization` header to the user's SOGo6 bearer token (from `POST /api/user/v1/auth/login`, or a
`make-token`/impersonation token).

### Raw smoke (no client needed)

```bash
# initialize
TOKEN="<sogo6-jwt>"
curl -s -D /tmp/h http://127.0.0.1:9000/mcp \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"smoke","version":"1"}}}'
SID=$(grep -i '^mcp-session-id:' /tmp/h | awk '{print $2}')

# list tools
curl -s http://127.0.0.1:9000/mcp -H "mcp-session-id: $SID" -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}'

# call a tool (path params as arguments, body/query under `data`)
curl -s http://127.0.0.1:9000/mcp -H "mcp-session-id: $SID" -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"agent.manifest","arguments":{}}}'
```

## Testing

```bash
# Unit / parity tests (sidecar venv; see "Running - Locally")
deploy/sogo6-mcp/.venv/bin/python -m pytest deploy/sogo6-mcp/test_server.py -q
# Makefile wrapper:
make test-mcp

# E2E smoke: fake facade + real sidecar over streamable HTTP
deploy/sogo6-mcp/.venv/bin/python deploy/sogo6-mcp/e2e_smoke.py
```

Covered: tool list == manifest (1:1), ≤ 30 tool cap, path params surfaced, token forwarded
verbatim, POST bodies sent as JSON, missing token → `S000208`, manifest resolution (live-first /
snapshot-fallback), path values percent-encoded.

## Keeping the snapshot current

The manifest snapshot must be regenerated whenever actions are added/renamed/removed in the
facade registry, otherwise the sidecar's tool list drifts from the server:

```bash
make snapshot       # runs sogo6-server's venv tool to regenerate deploy/sogo6-mcp/manifest_snapshot.json
git add deploy/sogo6-mcp/manifest_snapshot.json && git commit
```

Regeneration is deterministic: the snapshot is written *from the `ACTIONS` registry itself*
(plus `MANIFEST_VERSION`), never by hand.

## Container build

```bash
docker build -t sogo6-mcp:dev deploy/sogo6-mcp
```

Non-root user (`sogo`, uid 10001), `python:3.13-slim` base, only `fastmcp` + `httpx` installed.
